# ADR-0015：断言级区分「不符」与「无法求值」

| 字段 | 值 |
| :--- | :--- |
| 状态 | 已接受 |
| 日期 | 2026-10-13 |
| 来源决策 | `03-模块详细设计/TestExecutor.md` TE2 |
| 相关文档 | `03/TestExecutor.md` §3.2、`04-数据模型.md` §2.6 |

## 背景

断言求值的自然结果是两态：成立或不成立。

实现上也更简单：

```python
if 断言成立:
    outcome = "passed"
else:
    outcome = "failed"  # ← 「无法求值」也被归到这里
```

但断言存在第三类情况：**求值这个动作本身失败了**。

| 情况 | 例子 |
| :--- | :--- |
| 成立 | 状态码 200 == 期望 200 |
| 不成立 | 状态码 500 != 期望 200；`$.data.id` 不存在 |
| **无法求值** | **响应体不是合法 JSON**，`json_path` 无从取值 |

## 决策

**断言的求值结果为三态**：`passed` / `failed` / `error`。

`error` 专指**无法求值**，与请求层的失败（`case_results.status = 'error'`）是两个不同的概念，虽然用了同一个词。

持久化于 `case_results.assertion_outcomes`（`04` §2.6）。

**同时，用例级状态仍为四态**：`passed` / `failed` / `timeout` / `error`，其中：

| 条件 | 用例状态 |
| :--- | :--- |
| 请求超时 | `timeout` |
| 请求层失败（连接被拒、DNS、TLS） | `error` + `error_kind` |
| 请求完成，全部断言 `passed` | `passed` |
| 请求完成，其余情况 | `failed`（**不分 `failed` 与 `error`**） |

## 被否决的备选

### 备选一：断言级二态

**否决理由：下游无法分辨两种截然不同的失败。**

| 断言结果 | 推测的原因 | 排查方向 |
| :--- | :--- | :--- |
| 找 `$.data.id` 没找到（`failed`） | **服务端返回与文档不符** | 服务端缺陷 |
| 响应体根本不是 JSON（`error`） | **请求本身发错了**，或服务**返回了错误页面** | 请求侧 |

**这两条线索指向完全不同的排查方向。** 合并后，归因（`LogAnalyzer`）无法区分，用户拿到的排查建议是错的。

### 备选二：把 `error` 细分为更多状态

（如 `not_json`、`truncated`、`invalid_path`…）

**否决理由：**

- 状态越多，下游需要处理的分支越多，而多数分支不改变结论
- 具体原因已在 `assertion_outcomes[].reason` 字段中以文本表达，无需提升为状态

**原则：状态用于改变控制流，原因用于人理解。** 只有会改变下游行为（这里是归因方向）的区分才值得成为状态。

## 关于用例级为何不跟着分三态

用例级状态的第 4 条刻意不区分 `failed` 与 `error`：

> 对"这条用例通过了吗"这个问题，答案都是"否"。

若在用例级再分一档，所有下游判断都要处理第四个分支，**而它不改变任何结论**。区分留在断言级，由需要它的模块按需取用。

## 后果

**正面：**

- 归因能够分辨"服务缺陷"与"响应不是 JSON"这两类原因
- 无法求值时可携带具体原因（如 `response_truncated`，对应 ADR 未覆盖的 `04` DM6 截断场景）

**代价：**

- 断言结果的结构比二态复杂，需要独立的 JSONB 字段承载
- 用例级状态与断言级状态的语义需要区分理解（文档中明确说明了两者的关系）

**为什么本决策值得单独记录（重要）：**

合并在**代码上更短、看起来更干净**，容易被当作简化。

而且——**如果做错了，其他所有测试都是绿的**。

唯一能发现它的方式，是一个专门返回"200 但响应体不是 JSON"的测试端点（`09` §3.2 的 `/bad-json`）。

> **这属于文档中反复出现的一类风险**：做错了不报错、不影响正常流程、代码看起来更简洁。只有专门构造的场景能暴露。同一模式的还有：缓存命中率（ADR 未覆盖，`07` §5.3）、内网例外（ADR-0018）、覆盖率指标（ADR-0026）。
