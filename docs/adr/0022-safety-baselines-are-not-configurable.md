# ADR-0022：安全底线不做成配置项

| 字段 | 值 |
| :--- | :--- |
| 状态 | 已接受 |
| 日期 | 2026-10-13 |
| 来源决策 | `10-部署运维.md` OP1、`05-API契约.md` API3 |
| 相关文档 | `10-部署运维.md` §3、`05-API契约.md` §2.1 |

## 背景

系统的行为中有一部分来自安全需求（SR-1 ~ SR-8）。这些行为需要决定：**是硬编码，还是做成可配置的开关。**

做配置项看起来更"灵活"、更"专业"：

```
是否拒绝云元数据地址：  [ ] 开  [x] 关
是否跟随重定向：        [ ] 开  [x] 关
```

另一个相关的问题是默认值：服务默认监听哪个地址。

## 决策

**① 安全底线硬编码，不提供开关。**

具体地，以下行为**在配置中不存在对应项**（不是"默认值为 true"，是**根本没有这个选项**）：

| 行为 | 依据 |
| :--- | :--- |
| 云元数据地址一律拒绝（含配置了内网例外时） | ADR-0019、`03/Guardrail.md` §4.5 |
| 不跟随重定向 | ADR-0020 |
| 破坏性方法未授权时拒绝 | `03/Guardrail.md` §5 |
| 白名单为 `scheme + host + port` 精确匹配，不通配、不继承子域 | `03/Guardrail.md` GR3 |
| 校验作用于解析后的 IP 并钉死连接目标 | ADR-0019 |
| 日志不写入凭证与请求/响应正文 | `07` §5.5、`08` §4.3 |

**② 服务默认绑定环回地址 `127.0.0.1`；绑定到非环回地址时强制要求 Token，未配置则拒绝启动。**

## 被否决的备选

### 备选一：把安全行为做成配置项，默认值取"安全"的一侧

最常见的做法——"默认安全，但允许用户按需关闭"。

**否决理由：可关闭的安全开关本身就是漏洞。**

具体会怎么出事——**这三种都是真实会发生的**：

| 场景 | 说明 |
| :--- | :--- |
| **被误设** | 配置模板中默认值写成"关"（复制粘贴或笔误），用户未注意 |
| **被复制** | 有人为本地调试方便关闭了它，随后把配置复制到了生产 |
| **临时关闭后遗忘** | "我先关掉测一下，等下记得开回来" |

**而且这三种都不会产生任何报错。**

### 备选二：做成配置项，但关闭时需要二次确认

**否决理由：**

- 二次确认只是**降低了误操作概率**，没有消除"关闭是可能的"这一根本问题
- 在生产环境中，配置文件通常由脚本或编排工具写入——**二次确认在这一路径上不存在**
- 依赖用户的注意力来维持安全边界，等于把安全带交给用户自己系

### 备选三：全部写死，包括阈值类参数

**否决理由：**

阈值类参数（QPS 上限、超时时间、并发数、保留天数）**必须可配置**——它们的正确值取决于运行环境（目标服务的承受能力、网络状况、可用资源），无法在设计时确定。

把它们写死会使系统无法适配真实环境。

## 判断标准

> **改了这个值，会不会让安全性变差？**
>
> - **会** → 硬编码，不提供开关
> - **不会**（只影响性能、体验、兼容性） → 做成配置项

按此标准：

| 可配置（阈值与偏好） | 不可配置（安全底线） |
| :--- | :--- |
| QPS 上限、熔断阈值 | 元数据地址拒绝 |
| HTTP 超时、重试次数 | 重定向不跟随 |
| Worker 并发数 | 破坏性方法默认拒绝 |
| 数据保留天数 | 白名单精确匹配规则 |
| 内网例外**列表**（ADR-0018） | 校验作用于实际 IP |
| 规模上限、上传大小上限 | 日志脱敏范围 |

**注意"内网例外列表"是可配置的**——它是一份**白名单**（增加条目会放宽限制，但这正是设计意图，且需用户显式输入）。而"是否检查内网"不可配置。**区分在于：配置项是在受控地调整边界，还是在关闭边界。**

## 关于默认绑定地址

选择"默认只监听 `127.0.0.1`"而非 `0.0.0.0`，理由与上同源：

| 方案 | 用户的处境 |
| :--- | :--- |
| 默认 `0.0.0.0` | 用户**必须知道**自己需要关掉它，否则服务已对局域网开放 |
| 默认 `127.0.0.1` | 用户**无需知道任何事**即为安全；需要暴露时主动承担代价 |

MVP 是单机自用（PRD §5），绝大多数用户不需要对外暴露。而不小心以 `-p 0.0.0.0:3000` 启动的后果是——**整个测试平台（含加密凭证存储）对局域网开放**。

> **这是"默认安全"而非"默认开放"**，与很多软件的做法相反。区别在于：**默认安全不要求用户具备任何先验知识。**

## 后果

**正面：**

- 安全行为无法被误配、误复制、误遗忘
- 安全边界不依赖用户的注意力
- 配置面收窄，`config.py` 的清单更易审查

**代价：**

- 用户无法通过配置绕过某些限制（这是设计意图，但需要文档说明，避免用户误以为是缺陷）
- 某些合法的边缘场景无法通过配置解决，只能改代码

**实现约束：**

- 上述六项行为**不得出现在 `Settings` 中**（`08` §3）
- 启动期校验：绑定非环回且未配置 `api_token` → **拒绝启动**（`10` §5）

> **非法配置应在启动时失败，而非运行时。** 一个"服务起来了但对局域网裸奔"的状态，比"启动失败并给出明确原因"危险得多。
