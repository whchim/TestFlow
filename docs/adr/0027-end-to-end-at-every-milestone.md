# ADR-0027：每个里程碑都必须端到端可跑

| 字段 | 值 |
| :--- | :--- |
| 状态 | 已接受 |
| 日期 | 2026-10-13 |
| 来源决策 | `11-开发路线图.md` RM1 |
| 相关文档 | `11-开发路线图.md` §1、§3 |

## 背景

开发分为 6 个里程碑（M0 ~ M5）。有两种组织方式：

| 做法 | 顺序 |
| :--- | :--- |
| **A. 分层完成** | 先实现所有模块（解析器、生成器、执行器、归因、报告），最后集成并跑通 |
| **B. 端到端打通** | 第一个里程碑就打通整条链路（每一段都很简陋），随后逐段提升质量 |

**这是本项目的排期哲学，影响每个里程碑的形态。**

## 决策

**采用做法 B。每个里程碑结束时，系统都必须能从一个 Spec 跑出一份报告。**

不允许"这个阶段只做了半个流程"。

配套要求：

| 要求 | 说明 |
| :--- | :--- |
| **M1 的安全底线不延后** | ADR-0002、ADR-0018 ~ 0022 的核心约束在 M1 就位 |
| **M1 必须产出生成质量数字** | 哪怕很差（见下） |
| **每个里程碑的验收针对具体设计点** | 而非"跑一遍看看" |

## 被否决的备选

### 备选一：分层完成（A）

**否决理由——核心论据：**

> **一个大系统最大的风险不是"某个函数写错了"，而是"部件之间对接不上"。**

集成类问题包括：

| 类别 | 本项目中的具体形态 |
| :--- | :--- |
| 跨进程通信 | Celery 回调唤醒图（ADR-0008） |
| 崩溃恢复 | Checkpoint 重放与幂等（ADR-0010、0011） |
| 数据一致性 | 两个存储源冲突时听谁的（ADR-0009） |
| 安全拦截误伤 | 内网例外配置错误导致正常请求被拒（ADR-0018） |

**这些问题有一个共同特点：只有整条链路都通时才会暴露。**

按做法 A，所有对接问题会**堆到最晚、最贵的时刻一起爆发**。而且那时距各模块的实现已过去数月，细节已被遗忘。

### 备选二：端到端打通，但安全底线推迟到后期

即"先把功能跑通，安全最后统一加"。

**否决理由：**

- **"以后再补安全"是最容易永远补不上的事**，尤其当系统已经"能用"之后
- Guardrail 的 `policy.py` 是**纯函数**（`09` §2.2），成本低、易测试——它被推迟的唯一理由是"先跑通再说"，而这个理由不成立
- **一旦安全校验不在链路中**，整条链路的调试都缺少它的反馈（例如内网例外配置错误会以"请求失败"的形式表现，而不是清晰的拒绝原因）
- 从架构角度，ADR-0002 要求 Guardrail 是唯一出站通道——若后期才插入，等于要改造所有既有出站代码

### 备选三：端到端打通，但不要求 M1 产出质量数字

即 M1 的验收只检查"链路通了"。

**否决理由：**

**这个项目最大的不确定性是"AI 到底能不能生成出可用的用例"。**

如果 M1 只验证链路，那么这个核心假设**完全没有被触碰**——投入数月后，仍然不知道项目能不能成立。

**决策：M1 必须产出一个真实数字，哪怕很难看。**

例如"AI 生成的 100 条用例，人工审阅后采纳了 20 条"——**即使只有 20%，也必须有一个真实数字**。

有数字才能定位问题：

| 可能的原因 | 对应的调整方向 |
| :--- | :--- |
| Prompt 写得不好 | 调整提示词 |
| 给 AI 的信息不够 | 调整 schema 片段的裁剪与注入 |
| 模型能力不足 | 换档位（这正是 `09` §5.5 的方法论要解决的） |

## 后果

**正面：**

- 集成风险**早期暴露**，此时修复成本最低
- 每个里程碑都有可演示的成果，进展可验证
- 最大的技术不确定性（ADR 未覆盖，见 `11` §4.2）在 M1 即被消解

**代价：**

- **早期每个阶段的产物都很简陋**：AI 生成质量差、无归因、无界面
- 需要接受"当前版本不完整"，而不是"当前版本已完成一半"

**这是刻意的取舍。M1 的目标是"通"，不是"好"。**

## 验收项的组织原则

每个里程碑的验收动作**不是"跑一遍看看"，而是针对一个已知会静默失效的设计点**：

| 验收动作 | 验证的设计点 | 做错了会怎样 |
| :--- | :--- | :--- |
| 人为丢弃一次回调，图仍能推进 | ADR-0008 兜底轮询 | **其余测试全绿** |
| 用 `/bad-json` 跑一次 | ADR-0015 断言三态 | 合并两态代码更短，**只有此端点能发现** |
| Spec 指向内网 + 不配例外 → 拒绝 | ADR-0018 | **其他测试全部通过** |
| 缓存命中 token > 0 | `TG6`（`03/TestCaseGen.md` §8.3） | 缓存失效无任何报错，只是账单变贵 |
| 故意不注入 Guardrail 客户端 → 行为测试失败 | ADR-0002 | 静态检查无法覆盖，仅运行期有事实 |

**可复用的原则**：

> **验收项应优先覆盖那些"如果做错了，其他测试依然全绿"的地方。**

这类错误最危险——不报错、不影响正常流程、代码看起来更简洁，**只有专门构造的场景能暴露它**。
